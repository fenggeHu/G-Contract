# Content Pack Contract (Manifest and Def Schema)

- Status: Active
- Updated: 2026-09-15

> This document is the **interface protocol** between the engine team and the World team. Contract changes must follow the compatibility policy in overview.md.

## 1. Content Pack Directory Structure (`G_World/`)

```
G_World/
  base/core/                     # Base rules and common Defs
  packs/continent_aurelia/       # Continent: terrain/city coordinates/biomes
    manifest.json
    defs/{biomes,cities,caves}/*.json
    scenes/ironhold_gate.scene
    scripts/quest_gate.gd
  packs/dlc_northlands/          # Later-added content pack, without changing the engine
```

`G_Engine/` and `G_World/` have **separate repository and CI boundaries**; content is delivered as PCK (`_meta.json` declares the `content` version and `schema_major`), with independent versions and independent permissions. Content changes **never trigger** an engine recompile. See internal platform doc.

`_meta.json` (generated by `content build` at the content root, packaged with the PCK):
```json
{ "content": "0.9.0", "schema_major": "1" }
```
After the engine mounts the PCK at startup, it validates that `schema_major` ∈ the engine-supported set; otherwise it **refuses to start** (see [content-tooling.md](content-tooling.md) §5).

## 2. Manifest Specification

```json
{
  "id": "world.continent.aurelia",
  "version": "1.4.0",
  "schema": "1.0",
  "requires": { "engine": ">=1.2 <2.0", "packs": ["base.core@1.x"] },
  "capabilities": ["scene.switch@>=1.0", "world.stream@>=1.0", "script.gdscript@>=1.0", "render.light2d@>=1.0"],
  "loadAfter": ["base.core"],
  "entry": { "worlds": "worlds/", "defs": "defs/", "scenes": "scenes/", "scripts": "scripts/", "i18n": "i18n/" }
}
```

| Field | Required | Description |
|---|---|---|
| `id` | Yes | Globally unique, lowercase dot-separated naming |
| `version` | Yes | This pack's SemVer |
| `schema` | Yes | Content Schema version used |
| `requires.engine` | Yes | Engine version range |
| `requires.packs` | No | Other content packs depended upon |
| `capabilities` | Yes | Required engine capabilities, supporting `name@>=X.Y`; if missing/version unsatisfied, loading is refused |
| `loadAfter` / `loadBefore` | No | Load order |
| `entry` | Yes | Directories for each content type; `entry.i18n` points to this pack's translation CSV directory |

At engine startup it validates: capability missing / version unsatisfied / dependency missing → **refuse to load and provide readable remediation advice**.

**i18n (optional)**: after declaring `entry.i18n`, the pack enters **strong validation** — the Def's `labelKey` and dialog's `textKey` must have non-empty translations in every locale column (`content lint` reports `LOC_KEY_MISSING`). CSV conventions and runtime behavior are in internal platform doc.

## 3. Def Specification (data-driven, no code)

```json
{
  "type": "city",
  "id": "ironhold",
  "label": "Ironhold",
  "worldPos": { "x": 2410, "y": 1180 },
  "gateScene": "scenes/ironhold_gate.scene",
  "landing": { "radius": 64, "requires": ["flight"] },
  "biome": "highland",
  "lighting": { "profile": "lotr_bright", "timeOfDay": "golden" }
}
```

Rules:
- All content is expressed with `Def`, and `type` corresponds to a Def type registered by the engine.
- For the JSON syntax of inheritance and Patch, see [content-schema.md](content-schema.md) §0.
- Gameplay logic changes go into `scripts/`, not into data.
- Field-level definitions are governed by [content-schema.md](content-schema.md).

## 4. Versioning and Compatibility

| Object | Rule | Commitment |
|---|---|---|
| Content Schema | Independent `MAJOR.MINOR` | The engine declares the set of supported Schema major versions (≥ the latest two); machine-readable as `capabilities.json.schemaSupported` |
| Content pack | Each pack has independent SemVer | Declares engine/dependency ranges |
| Def fields | Add-only, never remove (unless MAJOR) | Removing a field requires deprecation one MAJOR in advance |

**Rejection policy (enforced by the engine/validator)**
1. Pack `schema` major version ∉ `schemaSupported` → **refuse to load** (`content validate` reports `SCHEMA_INVALID`).
2. `requires.engine` range does not satisfy the current engine → **refuse** (`DEP_MISSING`).
3. Declared capability missing / deferred / version below the minimum → **refuse** (`CAP_MISSING`).

**Deprecation and announcement (A1)**
- Deprecation of fields / capabilities / protocol messages: first announce in CHANGELOG.md, then retain for at least one **MINOR** cycle (warning only); removal requires a **MAJOR** bump.
- Contract freeze: before entering a milestone, freeze `capabilities.json` and the Content Schema major version; during the freeze period, only MINOR additions are allowed.

## 6. Asset Licensing Registry (`licenses.json`)

Each pack may optionally provide `<pack>/licenses.json`: asset **file path** → licensing entry.

```json
{
  "scenes/dummy.tscn": { "license": "CC0-1.0", "source": "in-house", "author": "G3" }
}
```

| Field | Required | Description |
|---|---|---|
| `license` | Yes | SPDX identifier or license name |
| `source` | No | Source (in-house / purchased / external link) |
| `author` | No | Author / attribution |

- `content lint` validates: `license` is non-empty; **asset files referenced by scenes** (`scene.file` / `scene.terrain`) must be in the registry, otherwise it reports `LICENSE_MISSING`.
- If no `licenses.json` is provided and the pack contains scene assets → **warning** (gradual adoption, non-blocking).
