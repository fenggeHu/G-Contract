# Contract: Content Integration Guide

- Status: Active
- Updated: 2026-09-20

> Entry point for **content creators** consuming this repository. Field-level rules live in the linked contracts; this guide only describes the end-to-end integration steps for the current capabilities. Requests/open questions: file a `content-handoff` issue (do not edit mirrored files).

## 1. Consuming the contract

- This repository is a **read-only mirror** generated by the platform; changes go through an Issue → platform contract PR.
- Pin a version from the Releases: `content` (CLI), `contract.zip`, `release.json`, `engine-devkit-lite-<ver>.zip`.
- Validate before building:
  ```bash
  content verify-release --release release.json --caps shared/contract/capabilities.json
  content validate --sdk <dir> --content <your content root>   # <dir> = capabilities.json + schema/content-<ver>.json
  content lint --sdk <dir> --content <your content root>
  ```
- Current content Schema is **1.4** (major `1`; older packs still load with a warning). Compatibility window: `capabilities.json.schemaSupported`. See [content-tooling.md](content-tooling.md).

## 2. Player appearance (parameterized)

**Declare** a `species` Def: a presentation scene plus a customization parameter table.
- `presentation`: pack-relative `.tscn` path.
- `params[]`: `{ id, kind: color|enum|float|int, default, min?, max?, step?, options?(enum), part?, labelKey? }`.
- Reference it from `character.species` (player) and `npc.species` (NPCs use the defaults).
- Full fields: [content-schema.md](content-schema.md) §28; minimal example + common errors: [content-examples.md](content-examples.md) §25.

**Provide** the presentation scene: its root script implements `apply_params(params: Dictionary) -> void` and maps the normalized params to visuals. Assets go into `licenses.json`. Content scripts must not reference `res://engine|main|ui|tests` (access the engine only through `engine/sdk`).

**Character creation UI**: use `Appearance.normalize(species_def, params)` for legal ranges/defaults, then `Player.set_appearance(species_id, params)`. Preview/apply with `Appearance.apply(species_def, params)` or `PlayerCharacter.set_appearance(params)`. See [engine-sdk.md](engine-sdk.md) §2.1/§3.

**Other players' appearance**: snapshot entities carry `species` + `akey` (a cache key `<species>@<hash>`). On a cache miss call `NetClient.appearance_get(user_id, species)`, then render with `Appearance.apply`; key the cache with `Appearance.key(species, params)` (same as `akey`). The full params are persisted as `player.appearance` and normalized server-side. See [protocol.md](protocol.md) §8 and [save-schema.md](save-schema.md) §2/§10.

## 3. Entering the persistent world

- Configure a default spawn: `world.defaultEntry` → a `poi` id; ensure `poi.worldPos` is in **meters** (±4096) with a correct `altitude`. Absent → world center.
- Online entry:
  ```gdscript
  await NetClient.enter_world(prefer_poi?)   # RPC enter_world → authoritative spawn
  SceneManager.to_world(entry, poi_id)        # adopts NetClient.world_spawn automatically
  ```
- **Always adopt the server spawn** from `world_welcome.spawn`; do not recompute it locally. Login spawn priority: saved `player.location` → `world.defaultEntry`/`poi`. Reconnect is handled by `NetClient`.
- Messages/RPCs: [protocol.md](protocol.md) §8.

## 4. Contract / dependency upgrade checklist

- Set `manifest.schema` to `"1.4"` (major `1` remains compatible; older packs load with a warning).
- Declare the capabilities you use: `appearance.apply@>=1.0`, `world.presence@>=1.0` (plus `scene.switch`).
- Pin the new artifacts and bump your `deps.json`; run `content verify-release` + `content validate` + `content lint`.
- Add `labelKey` translations for any user-visible `species` / `params[].labelKey`.
